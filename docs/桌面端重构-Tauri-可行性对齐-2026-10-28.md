## 0. 一句话结论

**可行**，但必须先纠正一个语义：softlib 的"无后台模式"是 **"客户端不需要另起本机后台进程、也不另开后台窗口"**，不是"把授权服务端塞进安装包"。

推荐目标形态：

```
Tauri 2 壳（Rust）
├─ WebView: React 18 + TS + Vite   ← 登录门 / 主界面 / 账号安全 / 套餐 / 管理面板
│     └─ HTTP(S) ──→ Node 授权后台（192.168.3.123:3010，保持远程）
└─ Rust commands / sidecar          ← Win32 全局钩子同步引擎、单实例、本地令牌
```

授权后台**留在远程**；"前后台封装在一起"只发生在两个层面：
1. 客户端：UI + 本地能力封装进一个 exe（Tauri），用户双击即用；
2. 部署侧（可选）：把管理台静态资源内嵌进 Node 进程，运维只需分发 1 个 `server.js`。

## 2. "无后台模式"的三种读法与对齐结论

| # | 读法 | 含义 | 判定 | 理由 |
|---|---|---|---|---|
| A | 无本机后台进程 | 客户端不启动/看护本地服务，只连远程授权后台 | ✅ 采纳 | 与现状一致（现在连 `.123:3010`），softlib 也是这么做的 |
| B | 无独立后台窗口 | 管理界面并入客户端，同一窗口内 F2 触发管理登录 | ✅ 采纳 | 正是"触发管理登录"的落点；消灭 `admin.html` 另开浏览器 |
| C | 授权后台随客户端分发 | 把 `server.js` 的校验逻辑塞进安装包，本地判定到期/机器绑定 | ❌ 否决 | 授权判定一旦在客户端，等于把 `一账号一机`、`换绑扣 6h`、`封禁`、`续期` 全部交给攻击者；改本地时钟/内存即可白嫖。与现有商业模型直接冲突 |

> 若将来确实需要"完全离线授权"，只能做 **签名许可证文件（服务端私钥签、客户端公钥验）+ 短周期联网复核**，属于另一个立项，不在本次范围。

## 3. 目标架构与信任边界

```
┌──────────────────────── Tauri 2 窗口（单窗口） ────────────────────────┐
│ React 视图层                                                           │
│   /login  /register  /forgot  /security  /plans  /redeem               │
│   /main（同步主界面：窗口列表、角色、规则、开始/停止）                  │
│   /admin（F2 触发 → 管理员密码 → 管理面板）                             │
│        │                                                               │
│        ├── fetch → Node 授权后台（账号域 /api/auth/*，管理域 /api/admin/*）│
│        └── invoke → Rust commands                                      │
│                 ├─ 单实例锁 / 令牌存储(HMAC) / 审计日志                │
│                 ├─ 全局快捷键 F2                                        │
│                 └─ 同步引擎（sidecar 或原生，见 B1）                    │
└────────────────────────────────────────────────────────────────────────┘
                          │ 60s 心跳 + 到期前离线兜底（保留现状语义）
                          ▼
              Node 授权后台 .123:3010（权威：会话、机器绑定、时长、封禁）
```

信任边界（保持不变）：
- 时长、封禁、机器绑定、换绑次数 → **只信服务端**；客户端缓存只用于断网兜底。
- 管理员权限 → 服务端 `role/session` 判定；客户端隐藏入口只是 UX，不是安全边界。

### 10.4 与 Python 的三处差异（有意为之）

1. **空闲时状态列为 "—"**：Python 在未启动时 `target_states()` 对每个目标返回"正常"，
   界面因此显示"正常"但实际没有任何投递可观测。S2 明确显示 "—"，不谎报正常。
2. **设为主窗口时自动从次窗口列表剔除**：Python 允许同一 hwnd 同时是 main 和 target，
   直到 `start()` 才被过滤。S2 在设置主窗口时即移除，避免表格与引擎状态不一致。
3. **规则键位用下拉选择**：Python 用 `_KeyCaptureButton` 捕获真实按键；S2 未装钩子，
   改用下拉（数字/字母/F1-F12/方向键等）。S3 接钩子后换回捕获按钮。

### 10.6 S2 边界（不是缺陷，S3 处理）

### 11.8 偏离与风险
