# 开放接口 v1（服务端到服务端）

> 目的：以后新开一个平台（新网站 / 新客户端 / 小程序后台），**不再自己存一套账号密码**，
> 而是把用户同步进本站，直接复用本站的注册、登录、套餐、时长、换绑、封禁体系。
> 一句话：**一个用户，一个密码，一套授权，多端通用。**

接口前缀：`http://192.168.3.123:3010/api/open/v1/`

```
对方平台后端 ──HMAC 签名──► 本站 server.js ──► users.json / identities.json
     │                                              │
     └── 拿到 token 后可直接用本站 /api/auth/me 校验 ┘
```

## 1. 启用（默认关闭）

未配置时整个 `/api/open/v1/*` 返回 **501 OPEN_API_DISABLED**，外部摸不到任何东西。

在服务器 `/home/zxzjxx/hzkey/hzkey.env` 里加一行（一行可配多个应用，逗号分隔）：

```bash
HZ_OPEN_APPS=shopv1:Kq7sV2mZ9pR4xT8w,miniapp:Bn3cF6hJ1lQ5tY0u
#             ^app_id  ^secret(≥16 位)   ^第二个应用的 app_id : secret

# 需要跨应用读写（老平台整体迁移）时, 在 secret 后面用 | 指定 scope:
HZ_OPEN_APPS=shopv1:Kq7sV2mZ9pR4xT8w|all,miniapp:Bn3cF6hJ1lQ5tY0u
#                                     ^ 不写 = own (默认, 只能碰自己代注册的账号)
```

```bash
# 改完重启生效
ssh zxzjxx@192.168.3.123 '/home/zxzjxx/hzkey/hzkey.sh restart'
curl -s http://192.168.3.123:3010/api/ping        # 确认还活着
```

| 规则 | 说明 |
|------|------|
| app_id | 建议 `^[a-z0-9_-]{3,32}$`，会写进审计日志，一眼看出是哪个平台干的 |
| secret | 至少 16 位，建议 24 位以上随机串；**只放在对方服务器环境变量里**，不进前端、不进 Git |
| 隔离 | 默认 `own` scope：每个 app 只能读写**自己 `external_id` 映射出去的用户**；用别家的用户名/ext 越界 → 403 `OUT_OF_SCOPE` |
| scope | `own`（默认）/ `all`。`all` = 可以读写全站任意账号，只给"要接管历史会员"的自有平台，别给经销商 |
| 轮换 | 换 secret 只需改 env + 重启；旧 secret 立刻失效（无灰度期，选低峰做） |
| 关闭 | 删掉这一行重启，接口整体变 501（已同步的账号不受影响，仍可正常登录） |

## 2. 签名（每个请求都要）

请求头：

| 头 | 值 |
|----|----|
| `x-app-id` | 你的 app_id |
| `x-timestamp` | 当前毫秒时间戳（13 位），与本机时间偏差 **> 5 分钟**直接拒 |
| `x-nonce` | 随机串，`[A-Za-z0-9_-]{8,64}`，**5 分钟内不可重复** |
| `x-signature` | 见下 |
| `Content-Type` | `application/json` |

待签串（换行 `\n` 分隔，任何一项变了签名就失效）：

```
METHOD
PATH
app_id
timestamp
nonce
sha256hex(rawBody)
```

- `PATH` 是**不含域名、不含 query** 的路径，例如 `/api/open/v1/users/register`
- `rawBody` 是发送的**原始字节**（GET 用空串，即 `sha256hex("")` =
  `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`）
- `signature = HMAC-SHA256(secret, 待签串)`，**十六进制小写**

```js
// Node (零依赖)
const crypto = require("crypto");
function sign(method, path, appId, secret, bodyObj) {
  const raw = bodyObj ? JSON.stringify(bodyObj) : "";
  const ts = String(Date.now());
  const nonce = crypto.randomBytes(12).toString("hex");
  const canon = [method, path, appId, ts, nonce,
                 crypto.createHash("sha256").update(raw).digest("hex")].join("\n");
  const sig = crypto.createHmac("sha256", secret).update(canon).digest("hex");
  return { raw, headers: {
    "Content-Type": "application/json",
    "x-app-id": appId, "x-timestamp": ts, "x-nonce": nonce, "x-signature": sig,
  }};
}
```

```python
# Python (标准库)
import hashlib, hmac, json, os, time

def sign(method, path, app_id, secret, body=None):
    raw = json.dumps(body, separators=(",", ":"), ensure_ascii=False) if body else ""
    ts, nonce = str(int(time.time() * 1000)), os.urandom(12).hex()
    canon = "\n".join([method, path, app_id, ts, nonce,
                       hashlib.sha256(raw.encode()).hexdigest()])
    sig = hmac.new(secret.encode(), canon.encode(), hashlib.sha256).hexdigest()
    return raw, {"Content-Type": "application/json", "x-app-id": app_id,
                 "x-timestamp": ts, "x-nonce": nonce, "x-signature": sig}
```

> ⚠️ `raw` 一定要用**签名时那一份字节**去发送。先 `JSON.stringify` 再发，别让 HTTP 库自己重排字段。

curl 演示（PING，GET 无 body；`$TS`/`$NONCE`/`$SIG` 由上面的 JS/Python 片段算出）：

```bash
APP=shopv1; SECRET='Kq7sV2mZ9pR4xT8w'; TS=$(date +%s%3N); NONCE=$(openssl rand -hex 12)
BODY_HASH=e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
SIG=$(printf 'GET\n/api/open/v1/ping\n%s\n%s\n%s\n%s' "$APP" "$TS" "$NONCE" "$BODY_HASH" \
      | openssl dgst -sha256 -hmac "$SECRET" -r | cut -d' ' -f1)
curl -s http://192.168.3.123:3010/api/open/v1/ping \
  -H "x-app-id: $APP" -H "x-timestamp: $TS" -H "x-nonce: $NONCE" -H "x-signature: $SIG"
# {"ok":true,"app_id":"shopv1","api":"v1","time":1761...,"endpoints":[...]}
```

## 3. 接口清单

所有接口 `POST`，JSON 请求体，返回 `{"ok":true|false,...}`。
**HTTP 状态码只表达协议层结果**（401 签名错、429 限流、400 参数错、404 无此接口），
业务结果看 `ok` + `code`（比如"账号不存在"是 `200 + ok:false + code:NOT_FOUND`）。

### 3.1 `GET /api/open/v1/ping` — 握手

```json
{"ok":true,"app_id":"shopv1","api":"v1","time":1761640000000,
 "endpoints":["ping","users/register","users/status","users/extend","auth/verify","auth/login"]}
```
上线自检先打这个：签名通了再往下接。

### 3.2 `POST /api/open/v1/users/register` — 代注册（幂等）

| 字段 | 必填 | 说明 |
|------|------|------|
| `external_id` | ✅ | **对方平台的用户主键**（如 `shopv1` 的 `user_id`），1-64 字符 |
| `username` | ⬜ | 本站登录名；不填自动生成 `u_xxxxxxxx`；被占用返 409 |
| `password` | ⬜ | 不填则本站生成 14 位随机密码，**只在本次响应的 `initial_password` 里出现一次** |
| `recovery` | ⬜ | 安全码（用户忘记密码时自助用），8-32 位且含字母和数字 |
| `note` | ⬜ | 备注，管理员在会员列表能看到（默认 `来自 <app_id>`） |

```json
{"ok":true,"created":true,"user":"u_7f3a9c21","external_id":"shopv1_10086",
 "initial_password":"Xk7mQ2pRt9Lw4e","rc_set":false,"state":"none",
 "plan_id":"","plan_name":"","remaining":0,"expires_at":0,
 "machine":"","machine_ok":true,"rebind_left":3}
```

- **幂等**：同一个 `external_id` 再调多少次都只返回现状（`created:false`），不会造第二个账号
- `external_id` → 本站用户名的映射落在 `server/data/identities.json`
- 不赠体验时长（体验是按机器发的，归客户端注册那条链路）；要送时长请显式调 `users/extend`
- 响应**永远不含密码哈希、不含安全码原文**，只回 `rc_set` 布尔

### 3.3 `POST /api/open/v1/users/status` — 查状态

请求：`{"external_id":"shopv1_10086"}`（或 `{"username":"u_7f3a9c21"}`）

```json
{"ok":true,"external_id":"shopv1_10086","user":"u_7f3a9c21","state":"active",
 "remaining":2602799,"expires_at":1764239999000,"plan_id":"month","plan_name":"月卡",
 "rebind_left":3,"rc_set":true,"machine":"HZ-7F3A-9C21-BE04"}
```
账号不存在：`{"ok":false,"code":"NOT_FOUND","msg":"账号不存在"}`（HTTP 200）。

> 单位：`remaining` 是**秒**，`expires_at` 是**毫秒**时间戳（与 `user_remaining` 的秒口径不同，别混）。

### 3.4 `POST /api/open/v1/users/extend` — 加/减时长（权益同步）

请求：`{"external_id":"shopv1_10086","seconds":2592000}`

```json
{"ok":true,"user":"u_7f3a9c21","remaining":5194799}
```

- 正整数秒，单次上限 10 年（越界自动夹到上限）
- 用在：对方平台买了订阅 → 折算成秒同步过来；补单、活动赠送、数据迁移同理
- 写的审计动作是 `OPEN_EXTEND`，管理台审计日志可查
- **不做幂等**：同一次补单别重试两遍，否则时长翻倍（建议对方用自己订单表的唯一键去重）

### 3.5 `POST /api/open/v1/auth/verify` — 令牌校验

请求：`{"token":"<本站发给用户的 token>","machine":"可选, 传了就比对机器码"}`

```json
{"ok":true,"external_id":"shopv1_10086","user":"u_7f3a9c21","remaining":2602799,"state":"active"}
```
失败码：`TOKEN_INVALID`（过期/伪造/已登出）、`MACHINE_MISMATCH`（令牌绑的是别的机器，或账号已在别处换绑）。

用途：对方平台拿到用户请求里的 token，问一句"这人是谁、还有多久"，**不用自己存用户名**。

### 3.6 `POST /api/open/v1/auth/login` — 账号密码登录

请求：`{"username":"u_7f3a9c21","password":"...","machine":"HZ-7F3A-9C21-BE04"}`

```json
{"ok":true,"token":"9f2c...","rebound":false,"cost_seconds":0,
 "external_id":"shopv1_10086","user":"u_7f3a9c21","remaining":2602799,
 "expires_at":1764239999000,"state":"active","plan_name":"月卡","rebind_left":3}
```

- **和客户端 `/api/auth/login` 是同一个核心函数**（`user_login_core`）：限流、失败锁定、换绑扣时、审计全都一致
- 因此**这里发的 token，拿去调客户端接口 `/api/auth/me` 一样有效**（同一套登录）
- 换绑规则不变：机器变了扣 6 小时、最多 3 次；`rebound:true` 时 `cost_seconds` 是扣掉的秒数

## 4. 错误码

| code | HTTP | 含义 / 处理 |
|------|------|------------|
| `OPEN_API_DISABLED` | 501 | 本站没配 `HZ_OPEN_APPS`，先找管理员开 |
| `APP_UNKNOWN` | 401 | `x-app-id` 不认识（没配 / 拼错） |
| `TS_INVALID` | 401 | 时间戳格式不对或偏差 > 5 分钟 —— 先校时（NTP） |
| `NONCE_INVALID` | 401 | nonce 长度/字符不合规 |
| `SIGN_BAD` | 401 | 签名不对 —— 90% 是 PATH 带 query、body 被重排、secret 不对 |
| `NONCE_REPLAY` | 401 | 同一 nonce 二次使用；每次请求都要新随机 nonce |
| `USERNAME_TAKEN` | 409 | 指定 `username` 已被占用（换一个，或不传让它自动生成） |
| `NOT_FOUND` | 200 | 账号/映射不存在 |
| `TOKEN_INVALID` / `MACHINE_MISMATCH` | 200 | 见 3.5 |
| `NO_SUCH_ENDPOINT` | 404 | 路径写错 |
| `OUT_OF_SCOPE` | 403 | 该账号不属于本应用（只有 `own` scope）。要跨租户请让管理员改配置 |
| — | 413 | 请求体超过 64KB（直接回状态码，不再断连） |
| — | 429 | 全局限流 240 次/分钟/IP（`/api/ping` 不计入）；`auth/login` 30 次/分钟；签名连错 20 次锁该 app 5 分钟 |

**签名错误计数是连坐的**：一个 app 连错 20 次，这个 app 的所有请求都会被锁 5 分钟（不影响别的 app）。
所以别在循环里拿错 secret 硬试。

## 5. 审计与环境变量

审计日志（`server/data/audit.log`，JSONL）里这些动作的 `user` 字段就是 `app_id`：

| action | 触发 |
|--------|------|
| `OPEN_REGISTER` | 代注册成功（detail: `外部ID=...`） |
| `OPEN_EXTEND` | 加时长（detail: `+秒数 剩余=...`） |
| `OPEN_LOGIN_OK` / `OPEN_LOGIN_FAIL` | 代登录 |
| `OPEN_BADSIGN` | 签名/时间戳/nonce 任何一项不合规（detail 是错误码） |
| `OPEN_OUT_OF_SCOPE` | 越权访问别家账号（detail: 被拒绝的账号名） |

> 日志里**不记 secret**，也不记密码和安全码（`tests/test_open_api.py` 有断言守住这条）。

| 环境变量 | 默认 | 作用 |
|----------|------|------|
| `HZ_OPEN_APPS` | 空（=关闭） | `app_id:secret[\|own,all][,app_id:secret...]` |
| `HZ_REG_PER_MIN` | `6` | 注册限流（每 IP 每分钟）。**生产别动**，只在跑集成测试时调高 |

## 6. 接入方的标准姿势

```
1. 用户在你的平台注册 → 你调 users/register(external_id=你的 user_id)
   → 拿到 user（本站用户名）；没传密码就把 initial_password 展示一次，或引导用户自己登录改密
2. 你的平台要判断"这人有没有权限用某功能" → 调 users/status 看 state + remaining
3. 用户在你的平台买了订阅 → 调 users/extend 把权益折算成秒同步过来
4. 用户在你的平台登录 → 调 auth/login 拿 token，把 token 存进你的会话
   → 之后每次请求调 auth/verify（可带 machine）确认还有效
5. 用户忘记密码 → 本站客户端有「忘记密码 + 安全码」自助；你的平台只需把入口指过来
```

## 7. 还没做的（预留，按需再加）

| 能力 | 现状 | 加的时候注意 |
|------|------|-------------|
| 改密 / 重置密码 | 未开放 | 建议只允许 `external_id` 本人触发，并吊销该账号全部会话 |
| 封禁 / 解封 | 未开放 | 管理台已能做；开放需单独权限位，别给同一个 app 全给 |
| 解绑设备 | 未开放 | 会破坏"一账号一机"计费，需审计 |
| 批量同步 | 未开放 | 应先做分页 + 幂等键，否则同步中断没法续 |
| 事件回调（到期提醒 / 支付成功） | 未开放 | 需要对方提供回调地址 + 自己的签名方案 |
| 接口级权限位 | **已做** `own` / `all` 两级 | 再细（改密/封禁/解绑单独授权）还要加按接口的位掩码 |
