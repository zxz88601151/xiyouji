## 商业流程（v4 主链路）

```
注册 ──► 登录 ──► 选套餐 ──► 支付 ──► 套餐开通 ──► 登录看到剩余时间
  │  (设安全码)                              ▲
  │                                          │
  ├─ 忘密码 ──► 用户名 + 安全码 ──► 重置密码 ─┘ (全部旧登录立刻失效)
  └──────── 兑换卡密（CDK 直接充时长）───────┘
```

| 环节 | 客户端行为 | 服务端 |
|------|-----------|--------|
| 注册 | 用户名 + 密码 + **安全码**（+ 确认） | 查重、强度校验（密码与安全码两把尺子）、scrypt 分别加盐入库、立即发令牌 |
| 登录 | 用户名 + 密码，可勾「记住我」 | 失败计数、锁定、发 30 天令牌 + 绑定本机机器码 |
| 找回密码 | 用户名 + 安全码 + 新密码 | 校验安全码 → 换 salt/hash → **吊销该账号全部会话** → 记 `RECOVER_OK` |
| 选套餐 | 只显示套餐名/时长/价格，**不参与计价** | `/api/plans` 下发；下单只认 `plan_id` |
| 支付 | 拿 `pay_params` 调起支付页 | 生成订单（pending），金额由服务端按套餐表算 |
| 开通 | 轮询 `/api/order/query` 直到 paid | 支付回调验签 → `order_complete`（幂等）→ 时长入账 |
| 看到时间 | 标题栏 + 顶部账号行显示「剩余 x天x小时」 | 心跳每次回传剩余秒数与到期时间 |

## 套餐与价格（服务端唯一权威）

价格单位是**分**，定义在 `server.js` 的 `PLANS` 常量里，客户端拿不到也改不了金额。

| 套餐 | plan_id | 时长 | 价格 | 标签 |
|------|---------|------|------|------|
| 日卡 | `day` | 1 天 | ¥5.00 | |
| 周卡 | `week` | 7 天 | ¥25.00 | 入门 |
| 月卡 | `month` | 30 天 | ¥69.00 | 最受欢迎 |
| 季卡 | `quarter` | 90 天 | ¥179.00 | 省 20% |
| 年卡 | `year` | 365 天 | ¥599.00 | 省 30% |

> 改价格：只改 `PLANS` 里对应的 `price` 数字（分）后重启服务即可，客户端下次打开自动刷新，**不用重新打包 EXE**。
> 加套餐：往 `PLANS` 数组里加一条 `{ id, name, days, price, tag }` 就行，管理台和客户端都是循环渲染的。

## 支付通道

`HZ_PAY_PROVIDER` 控制走哪条路：

| 值 | 说明 | 适用 |
|----|------|------|
| `mock`（默认） | 占位通道。下单后订单停在 pending，由**管理台「手动确认」**或客户端测试按钮置为 paid | 上线前联调、内测 |
| `epay` | 易支付协议。需要 `HZ_EPAY_PID` / `HZ_EPAY_KEY` / `HZ_EPAY_URL`，回调走 `/api/pay/notify` 做 MD5 验签 | 已开通易支付商户号 |

```bash
# 接易支付示例
HZ_PAY_PROVIDER=epay \
HZ_EPAY_PID=1001 \
HZ_EPAY_KEY=你的商户密钥 \
HZ_EPAY_URL=https://pay.example.com/submit.php \
HZ_PUBLIC_URL=https://你的域名 \
node server.js
```

安全约定（已实现）：
- 金额只在服务端算，回调只做「验签 → 查订单 → 校验金额一致 → 幂等置 paid」，客户端传什么金额都不看
- `order_complete` 幂等：同一订单重复回调不会重复加时长
- `/api/order/mock_pay` 在非 `mock` 通道下**直接 404**，生产环境不会被刷
- 支付回调必须 MD5 签名匹配，签名错一律 400 并记审计

## 卡密（CDK）在 v4 里的定位

CDK **不再是授权凭证**，降级为**充值码**：用户在客户端「兑换卡密」里输入，时长直接充进他的账号。

- 老用户手上的卡密继续有效，输入后按原逻辑折算时长入账
- 一张卡密只能兑换一次（已兑换的会记 `redeemed_by`）
- 兑换码仍可在管理台批量生成、加时长、封禁、导出

## 换机与换绑规则（v3 起「一账号/一卡 一机」）

v4 里设备绑定挂在**账号**上，规则与卡密时期一致：

| 场景 | 结果 | 代价 |
|------|------|------|
| 首次登录/激活 | 绑定本机机器码 | 无 |
| 同一台机器重复登录（重装/换目录） | 直接放行 | 无，不占换绑次数 |
| 换到新机器，同一账号登录 | 自动重绑到新机器，旧机下次心跳即报「账号已在其他机器登录, 本机已退出」 | **扣 6 小时 + 占 1 次换绑机会** |
| 管理台点「解绑」后在新机登录 | 同上 | 同上 |
| 换绑次数用完（默认 3 次） | 拒绝，提示联系客服 | —— |
| 剩余时长不足 6 小时 | 拒绝换绑，提示先续期 | —— |

- 换绑**不从零重算**时长，只从剩余时间里扣 6 小时。
- 上限与代价改在 `server.js` 顶部两个常量：`REBIND_MAX_TIMES`、`REBIND_COST_SECONDS`。
- 客户端**不再有 72 小时离线宽限**：只要账号/卡密没过期，断网也照常用（试用卡除外，试用按时长计费仍需联网）。
- 每次换绑都会在后台审计里留一条 `REBIND`，含新机器码、扣时、第几次。
- 一个账号同时只允许一台机器在线：`/api/auth/me` 会比对 `bound_machine`，不一致即让本机退出登录。

## 2）给 KEY 加时长（续期）

1. 登录后在「卡密管理」表格找到那张卡（可在搜索框输卡密/备注/机器码）
2. 点该行的 **「加时长」**
3. 弹窗里选快捷按钮（+1小时 / +1天 / +7天 / +30天 / +365天），或手填数量+单位
4. 点「确认加时长」→ 表格「剩余」「到期」立刻更新

规则说明：
- **已激活的卡**：从当前到期时间往后加（已过期的卡从现在起算）
- **还没激活的卡**：时长记为「待生效」，等用户激活时自动加上（表格状态列会显示 `待生效 +30天`）
- 客户换电脑：点 **「解绑」** → 剩余时长自动转入待生效 → 用户在新机器激活时时长不丢

## 3）生成账号（子账号 / 经销商）

只有 **owner** 能看到「子账号管理」区块：

1. 填 用户名（3-24位字母数字）、密码（≥8位）、角色、备注（比如"经销商老王"）
2. 点「创建账号」

| 角色 | 能做什么 | 不能做什么 |
|------|---------|-----------|
| **owner**（你） | 全部：发卡、加时长、封禁、删卡、管账号 | — |
| **admin**（经销商/客服） | 发卡、加时长、封禁、解绑、看日志 | 删卡、管账号 |
| **viewer**（财务/查账） | 只看卡密列表和统计 | 任何写操作 |

子账号管理操作：「重置密码」（对方下次登录强制改密）、「禁用」（立即踢掉他的登录）、「删除」。
审计日志区块能看到谁在什么时候做了什么（含 IP）。

## 4）会员管理（v4 新增）

顶部搜索框可按 **用户名 / 机器码** 搜，右侧下拉按状态筛（全部 / 正常 / 已到期 / 未开通 / 已封禁）。

表格每行显示：用户名、状态、套餐、剩余时长、到期时间、绑定机器（含 `换绑 n/3`）、累计付费、最近登录、**安全码（已设 / 未设）**。行内三个操作：

| 操作 | 效果 |
|------|------|
| **加时长** | 弹窗填数量+单位，直接给这个账号续期（补单、赔偿、活动赠送都用它） |
| **解绑** | 清掉绑定机器，用户下次可在新机登录；**注意：不扣时，等于白送一次换机**，客服慎用 |
| **封禁 / 解封** | 封禁会**立刻踢掉该账号全部在线会话**，客户端下次心跳就掉回登录页 |

## 5）订单管理（v4 新增）

按状态筛选（全部 / 待支付 / 已支付 / 已关闭），可按用户名或订单号搜。

- `mock` 通道下：点行内 **「手动确认」** 即把 pending 订单置为 paid 并给账号加时长（内测/补单用）
- `epay` 通道下：正常由支付回调自动置 paid，这里只用于**回调丢失时人工补单**——补单走同一个幂等函数，不会重复加时长
- 每笔订单记录：订单号、用户名、套餐、金额（分）、状态、创建时间、支付时间、通道

## 6）修改管理密码（2026-10-28 加固）

入口有两个：顶栏 **「修改密码」** 按钮，以及「子账号管理」里自己那一行的 **「修改密码」**（自己那行不再显示「重置密码」——那是不验原密码的后门，已封掉，走服务端会直接 400）。

弹窗三个字段：**原密码 / 新密码（至少 8 位，须含字母和数字）/ 确认新密码**，每个输入框右侧都有「眼睛」按钮可切换明文。

改密码会发生什么：

| 情况 | 结果 |
|------|------|
| 原密码不对 | 401「原密码错误」，并记一条 `CHANGE_PASSWORD_FAIL` 审计 |
| 新密码太弱（纯数字/纯字母/长度不合规/首尾空格） | 400，前端先拦一道、服务端再拦一道（`pwd_problem`） |
| 新密码 == 原密码 | 400 拒绝 |
| 两次新密码不一致 | 前端直接提示，不发请求 |
| 成功 | 返回 `revoked_sessions`，**该账号其它设备/其它浏览器的会话全部失效**，只有当前这个标签页继续可用；密码框自动收回明文 |

> 之前这里只校验长度，能把 owner 密码设成 `12345678`；现在这条已堵死。

## 7）会员忘记密码（安全码自助 + 客服兜底）

**安全码是什么**：注册时用户自己设的 8–32 位字母数字混合串，和密码分开存（各自独立 scrypt 加盐）。
它只干一件事：**忘记密码时证明"我是我"**。库里只有哈希，**管理台、客服、开发者都看不到原文**。

| 场景 | 用户怎么做 | 服务端行为 |
|------|-----------|-----------|
| 记得安全码 | 登录页右下角 **「忘记密码」** → 用户名 + 安全码 + 新密码 | 校验通过就换密码，并**吊销该账号全部会话**（在别的电脑上偷登的人立刻掉线），记 `RECOVER_OK` |
| 已登录，想补设/换安全码 | 主界面 **「账号安全」** → 安全码分组 → **当前密码** + 新安全码 | 必须验当前密码（只有令牌不够，防令牌被偷的人把账号"锁"到自己手里），记 `RC_SET` / `RC_SET_FAIL` |
| 忘了安全码 | 找客服；客服在「会员管理」看该会员这一列是 `已设` / `未设` | 客服侧只能确认"设没设"，**拿不到也不能代答**；用「重置密码」或让用户重新注册 |
| 会员列表里的「安全码」列 | `已设` = 有自助找回能力；`未设` = 老客户端注册的，只能客服处理 | 老客户端注册不带安全码仍放行（向后兼容），登录后可在「账号安全」补 |

防爆破（找回是唯一免登录的写操作，所以限得比登录更狠）：

| 维度 | 限制 |
|------|------|
| 每 IP | 20 次/小时（超了 429「找回请求过于频繁」） |
| 每账号 | 连错 5 次锁 **30 分钟**，锁定期内**正确安全码也拒绝**；第 5 次就明确告知还要等多少秒 |
| 防枚举 | 账号不存在 / 没设安全码时，也做一次等价耗时的 scrypt，并给**同一句**「用户名或安全码不正确」 |
| 封禁账号 | 直接「账号已被封禁, 请联系客服」，不给重置机会 |
| 审计 | `RECOVER_FAIL` / `RECOVER_OK`（含踢掉的会话数）/ `RECOVER_DENY` / `RC_SET` / `RC_SET_FAIL` 全部留痕 |

**安全码规则**与密码同尺子：≥8 位、≤32 位、必须同时含字母和数字、首尾不能空格，且**不能等于密码**。
注册页、找回页、账号安全页三处前端都做同样的预检（少一次"填完才知道不合规"），服务端再各拦一道。

# 三、管理员账号离线维护（G4 · reset_admin.js）

**什么时候用**：owner 密码忘了；或者把自己账号折腾进爆破防护锁定/禁用状态、后台进不去了。这是唯一的恢复入口，不依赖后台页面本身。

脚本：[server/reset_admin.js](file:///F:/zhuomian/%E5%A5%BD%E4%BA%BA%E5%A4%9A%E7%AA%97%E5%8F%A3%E5%90%8C%E6%AD%A5%E5%99%A8V10.0/%E5%A4%8D%E5%88%BB%E7%89%88/server/reset_admin.js)（零依赖），套一层 `hzkey.sh reset` 会自动「停服务 → 改 → 起服务」。

```bash
cd /home/zxzjxx/hzkey

./hzkey.sh reset --list                                   # 只看，不停服务
./hzkey.sh reset --reset --user admin --generate           # 生成强随机密码并重置
./hzkey.sh reset --reset --user admin --password 'NewPass2026'
./hzkey.sh reset --rename --user admin --to axin           # 换登录名
./hzkey.sh reset --create --user axin2 --role owner --generate   # 建第二个 owner，防单点
./hzkey.sh reset --reset --user admin --generate --dry-run # 预演，不落盘
```

行为约定（都已实测）：

| 点 | 说明 |
|----|------|
| 服务在跑就拒绝写 | 检测到 `data/hzkey.pid` 存活直接报错退出。原因：`server.js` 把 `admins.json` 读在内存里，运行期间改盘会被下一次写盘覆盖掉，改动凭空消失。加 `--force` 才强行写 |
| `--list` / `--dry-run` 是只读快路径 | 不用停生产服务，`hzkey.sh` 直接转调 node |
| 自动备份 | 每次写盘前生成 `data/admins.json.pre-reset-<时间戳>.bak` 等；回滚直接 `cp` 回来再 `hzkey.sh restart` |
| 踢会话 | 重置/改名会清掉该账号全部会话，旧浏览器的登录立刻失效 |
| 密码强度 | `--password` 走和服务端一样的 `pwd_problem` 校验，弱密码拒绝；`--generate` 生成 12 位字母数字混合 |
| 凭据落盘 | `--out <文件>` 把新密码写进文件（生产用的就是 `data/owner_password.txt`，权限 0600） |
| 禁用状态 | 账号是 disabled 时只改密码仍登不上，脚本会提示，需要一并 `--enable` |
| `--create` | 新账号 `must_change: true`，下次登录强制改密 |
| 改名后 | 记得同步改 `hzkey.env` 里的 `HZ_OWNER_NAME`（或重启时带上），否则服务新生成初始管理员时会用回 `admin` |

`HZ_OWNER_NAME`：初始 owner 的登录名，默认 `admin`。改它只影响**首次生成**，已有账号要改名请用 `--rename`。

# 四、开放接口（统一后台预留 ✅ 已实现，默认关闭）

目标：以后新开平台（新网站 / 小程序 / 新客户端）**不再自己存一套账号密码**，
把用户同步进本站，复用同一套登录、套餐、时长、换绑、封禁。
完整契约见 **[server/开放接口.md](file:///F:/zhuomian/%E5%A5%BD%E4%BA%BA%E5%A4%9A%E7%AA%97%E5%8F%A3%E5%90%8C%E6%AD%A5%E5%99%A8V10.0/%E5%A4%8D%E5%88%BB%E7%89%88/server/%E5%BC%80%E6%94%BE%E6%8E%A5%E5%8F%A3.md)**（签名算法 + 6 个接口 + 错误码 + curl/Python 示例）。

| 接口 | 作用 |
|------|------|
| `GET  /api/open/v1/ping` | 握手自检（签名通了才往下接） |
| `POST /api/open/v1/users/register` | 代注册，`external_id` 幂等，可自动生成用户名/初始密码 |
| `POST /api/open/v1/users/status` | 查用户状态与剩余时长 |
| `POST /api/open/v1/users/extend` | 把对方平台的订阅权益折算成秒同步过来 |
| `POST /api/open/v1/auth/verify` | 拿本站令牌问"这人是谁、还有多久" |
| `POST /api/open/v1/auth/login` | 账号密码登录，**与客户端登录共用同一核心函数**，发的 token 在 `/api/auth/me` 也有效 |

启用方法（不配就整体 501，外部摸不到）：

```bash
# /home/zxzjxx/hzkey/hzkey.env
HZ_OPEN_APPS=shopv1:Kq7sV2mZ9pR4xT8w,miniapp:Bn3cF6hJ1lQ5tY0u
#             app_id:secret(≥16位)  ,  第二个平台

# 要跨应用接管历史会员时才加 |all (默认 own: 只能碰自己代注册的账号)
HZ_OPEN_APPS=shopv1:Kq7sV2mZ9pR4xT8w|all,miniapp:Bn3cF6hJ1lQ5tY0u
```

```bash
ssh zxzjxx@192.168.3.123 '/home/zxzjxx/hzkey/hzkey.sh restart'
```

- 凭据只放对方**服务端**环境变量，不进前端、不进 Git；轮换 = 改 env + 重启，旧 secret 立即失效
- 安全：HMAC-SHA256 签名（METHOD/PATH/app_id/ts/nonce/sha256(body)）+ ±5 分钟时间窗 + nonce 5 分钟内不可重放
  + 全局限流 240 次/分钟/IP（`/api/ping` 不计）+ 该 app 签名连错 20 次锁 5 分钟
  + **租户隔离**：默认 `own` scope，只能读写自己 `external_id` 映射的账号，越界 403 `OUT_OF_SCOPE`；显式配 `|all` 才能跨租户
- 留痕：审计 `OPEN_REGISTER` / `OPEN_EXTEND` / `OPEN_LOGIN_OK` / `OPEN_LOGIN_FAIL` / `OPEN_BADSIGN`，
  `user` 字段就是 `app_id`；**日志与响应都不含 secret、密码、安全码**
- 映射：`external_id → 本站用户名` 落在 `data/identities.json`（原子写入 + 每日备份）

> 本轮**只实现、不启用**：还没有真实平台来对接，先不生成无主的 app 密钥。
> 有平台要接时按上面两行启用 + 把 `开放接口.md` 发给对方即可。

# 五、v2 安全加固清单（已实施）

| 项 | 措施 |
|----|------|
| 密码存储 | scrypt 哈希 + 随机盐，库中无明文；比较用 timingSafeEqual 防时序攻击 |
| 会话 | 32 字节随机 sid，HttpOnly + SameSite=Lax Cookie，12h 绝对过期 / 2h 空闲过期，登出即失效 |
| 爆破防护 | 登录 IP+账号双维度计数，10 次失败锁 15 分钟；账号不存在时也做等价耗时运算，防账号枚举 |
| 权限 | owner/admin/viewer 三级角色，每个写接口独立校验，越权写审计 `DENIED` |
| 账号生命周期 | 新建账号强制改密；禁用/重置密码立即踢掉其全部会话 |
| 输入校验 | 卡密/机器码/用户名/时长参数全部正则白名单，越界直接 400 |
| 撞库 | `/api/activate` 每 IP 20 次/分钟；全局 240 次/分钟 |
| XSS | 管理面板全部用 textContent 构建 DOM，卡密/备注不再 innerHTML 拼接 |
| 响应头 | nosniff、X-Frame-Options、no-store；管理页额外 CSP |
| 可用性 | 响应函数幂等 + uncaughtException/unhandledRejection 兜底，单点异常不会打挂服务 |
| 可追溯 | 登录/发卡/加时长/封禁/解绑/账号操作全记审计日志（时间、人、角色、对象、IP） |

## v4 账号/交易专项（已实施）

| 风险点 | 措施 |
|--------|------|
| 客户端改价 | 客户端下单只发 `plan_id`，金额由服务端 `PLANS` 表算；回调再校验金额与订单一致 |
| 重复加时长 | `order_complete` 幂等（同一订单第二次只回 `already:true`），支付回调重放无副作用 |

| 批量注册 | `/api/auth/register` 每 IP 6 次/分钟；注册即赠体验按机器去重（同一台机器只送一次） |
| 撞库 | `/api/auth/login` 每账号 8 次失败锁 15 分钟，锁定期内正确密码也拒绝 |
| 多人共享一号 | 令牌绑定机器码，`/api/auth/me` 每次比对；换机即旧机掉线并扣 6 小时 |
| 令牌膨胀 | 每账号最多保留 5 个会话，超出淘汰最旧；30 天绝对过期 + 7 天空闲过期 |
| 封禁不生效 | 封禁时立即删除该账号全部会话，客户端下次心跳（≤60 秒）掉回登录页 |
| 越权看别人的单 | `/api/order/query` 校验 `o.user === 当前账号`，否则回"订单不存在" |

## 2026-10-28 管理员改密专项（G1–G4，已实施）

| 编号 | 风险点 | 措施 |
|------|--------|------|
| G1 | 改密只查长度，owner 密码能被设成 `12345678` | 服务端 `pwd_problem()`：长度 8–64、必须同时含字母和数字、首尾不能空格；`users/create` 与 `users/reset_password` 用同一把尺子 |

| G2 | 页面没有改密入口/看不到自己填了什么 | 弹窗三字段（原密码 / 新密码 / 确认新密码）+ 三个「眼睛」切换明文；每次打开强制收回 `type=password` 并清空，不留上次的明文 |
| G2 | 改密后其它设备仍然在线 | 改密成功即吊销该账号**其它所有**会话，保留当前这个（`curSid`） |

| G4 | owner 密码忘了只能重装数据 | 离线维护工具 `reset_admin.js` + `hzkey.sh reset`（见本文件第三节）；pidfile 守卫防止服务运行期改盘被内存覆盖 |

## v4.1 找回密码 / 安全码 / 开放接口专项（已实施）

| 风险点 | 措施 |
|--------|------|
| 忘记密码只能人工重置 | 安全码自助找回 `/api/auth/forgot`；重置即吊销该账号全部会话 |
| 安全码本身泄露 | 只存 scrypt 哈希（独立盐）；接口/管理台/审计日志只出现"已设/未设" |
| 令牌被偷后清不掉找回能力 | 补设/更换安全码必须验**当前密码**（只有令牌不够） |
| 拿安全码当密码再撞一次 | 安全码不能等于密码；两把尺子同一套强度规则（8–32 位、字母+数字、首尾无空格） |
| 借找回接口枚举账号 | 账号不存在时做等价 scrypt，且返回同一句提示；`RECOVER_FAIL` 记真因（仅管理员可见） |
| 暴力猜安全码 | 每账号连错 5 次锁 30 分钟 + 每 IP 20 次/小时；第 5 次直接告知等待秒数 |
| 封禁账号靠找回复活 | 先判安全码再判封禁 → 「账号已被封禁, 请联系客服」并记 `RECOVER_DENY` |
| 新平台各存一套密码 | 开放接口代注册/代登录/校验/加时长，共用 `user_login_core` 一条路径 |
| 开放接口被抓包重放 | HMAC 签名 + ±5 分钟时间窗 + nonce 一次性；body 参与签名（改一个字节即失败） |
| 一个 app 出问题拖垮全网 | app 之间数据隔离；签名连错只锁该 app；未配置时整体 501 |

## 还没做的（按风险排序，需要时再说）

1. **HTTPS**：目前明文 HTTP。若走公网必须配 Nginx 反代 + SSL，并设 `HZ_SECURE_COOKIE=1`（Cookie 加 Secure）。**账号密码登录上线前这一条是硬门槛**，明文传密码等于裸奔
2. **真实支付通道**：`epay` 的验签骨架已就位，缺你的商户号 PID/KEY/回调域名；接了之后把 `HZ_PAY_PROVIDER` 改成 `epay`，`mock` 口子自动关闭
3. **客户端加固**：授权文件签名密钥在 `license_client.py` 的 `SECRET`，属混淆级，不防逆向高手；要硬抗需 VMP/加壳
4. **异常登录告警**：可加个定时任务扫 audit.log 里的 `LOGIN_FAIL` 并推送
5. **数据加密**：`keys.json` / `users.json` 明文落盘，服务器被入侵即泄露；需要可加静态加密
6. **会员忘记密码（已做 ✅）**：安全码自助找回已上线（见「一、7）」）；**仍未做**的是安全码也忘了的二次兜底——现在只能客服人工处理，要自助需接短信/邮箱
7. **开放接口的写操作**：改密/封禁/解绑/批量同步/事件回调尚未开放；`own`/`all` 两级 scope 已做，更细的按接口授权还没做，见 `开放接口.md` 第 7 节
